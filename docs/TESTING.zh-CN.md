# 验证说明

[English](TESTING.md)

## 自动化检查

使用 Java 25 运行 `./gradlew clean build`。测试覆盖容量及顺序、事件显示、配置校验及恢复、权限策略、本地化、JSON 与备份恢复、世界存储隔离、异步清空和写入竞争、最终落盘、过滤信息、原版包编解码、历史时间，以及回放失败后的目标客户端身份状态恢复。

`ReplayVisibilityTest` 使用 Mockito 创建 `ServerPlayer` 的模拟子类，并使用真实原版权限集合，调用实际 `visibleTo` 筛选入口。覆盖普通玩家和各 OP 等级下的三种聊天可见性、发送者与接收者过滤设置，以及自己消息的过滤例外。无需世界、连接或附加模拟代理。

协议测试初始化原版注册表及编解码器，并直接调用原版未签名验证器，不创建世界或连接客户端。数据包往返保留历史时间，但 `SignedMessageValidator.ACCEPT_UNSIGNED` 会将其重建为接收时间；测试明确覆盖这一限制。JUnit 不加载 Fabric Mixin；玩家信息包测试通过反射设置访问器的同一目标字段，以测试真正的原版序列化。因此测试通过不能证明运行时注入、真实服务端事件顺序或客户端接受行为。

快照和缓存回归测试覆盖 tick 末尾持久化、空闲 tick 不写入、配置立即缩容、清空待保存历史、停服最终记录、不可变快照复用、世界独立缓存淘汰、惰性解码和按接收者过滤。WorldHistory 测试使用模拟服务端 / 玩家上下文及真实文件，不启动游戏服务器。

## 手动验收——需要另行确认

使用可丢弃的测试安装及世界，不使用真实存档。记录服务端、模组、客户端版本和配置。成功构建 JAR 不代表已完成以下验证。

| 场景 | 预期结果 |
| --- | --- |
| Fabric 26.3 服务端、原版 26.3 客户端 | 无需客户端模组即可连接；补发包含本次已启用的进入公告；之后实时聊天正常。 |
| 正版模式、有效安全验证开启、`auto` | 玩家历史走系统消息，无历史签名或会话校验错误。 |
| 正版模式、`enforce-secure-profile=false`、`auto` | 未签名历史正常显示；客户端验证后时间为接收时间；回放结束后的实时签名聊天正常。 |
| 离线模式、`auto` | 未签名历史正常；重启和发送者重连不产生聊天校验错误。 |
| 各验证模式下的 `system` | 全部历史为系统消息，无需修改玩家信息状态。 |
| 开启“仅显示安全聊天” | 未签名历史可能被隐藏，系统路径表现与文档一致。 |
| 发送者离线、改名、重新登录，以及服务器重启 | 历史名称保留，存储时间不变（客户端显示受上述限制），Tab 无临时身份残留，当前会话正确恢复。 |
| 支持 26.3 的正式 Chat Patches | 记录确切版本；8.0.0 在当前未签名回放路径显示接收时间，系统消息同样不提供原始时间；验证后续实时聊天。 |
| 单人、未开启作弊的局域网房主、原版访客 | 主人可管理，普通访客无权管理，各自接收可见历史。 |
| 切换两个单人存档 | 历史隔离，安装目录配置共用。 |
| 私聊、队伍聊天、队伍可见死亡、Fabric 阻止消息 | 均不会泄漏到全服历史，公开事件遵守原版游戏规则。 |
| 文本过滤及聊天可见性 | 自己的消息遵守原版过滤例外，两种发送模式均不泄漏被过滤内容。 |
| 事件开关、缩容、错误配置和重载 | 显示、淘汰、有效配置、红色本地化提示及日志与 README 一致。 |
| 持续聊天时清空，随后重启及备份恢复 | 成功清空后旧消息不复活，新消息正常保留。 |
| 玩家仍在线时停服并重启 | 若启用退出事件，最终退出消息得到保存。 |
| 多行长消息和大量历史 | 确认原版窗口限制，不承诺分页或无限滚动。 |

启动实际 Minecraft 客户端、服务端游戏会话、单人或局域网测试前，必须另行确认。自动化构建不包含接受 EULA。
