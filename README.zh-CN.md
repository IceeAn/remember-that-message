# Server Chat History

[English](README.md)

适用于 **Minecraft Java 26.3** 的 Fabric 模组。玩家进入游戏时，补发当前世界最近的公开聊天记录。**服务端安装即可，原版客户端不需要安装本模组或 Fabric**。也支持单人世界及开放局域网的逻辑服务端。

0.1.0 使用 Java 25、Fabric Loader 0.20.1、Fabric API 0.165.0+26.3。项目名称暂定，模组 ID 为 `server_chat_history`。

## 安装

1. 使用 Java 25 和 Fabric Loader 0.20.1 创建 Fabric 26.3 服务端。
2. 将 Fabric API 0.165.0+26.3 和 `server-chat-history-0.1.0.jar` 放入 `mods` 目录。
3. 启动后自动生成 `config/server_chat_history.json`，历史文件保存在世界存档中。

单人或局域网游戏由房主在自己的 Fabric 实例安装上述模组，访客可以使用原版 26.3。本模组不会修改正版验证、安全配置或服务端 EULA。

## 记录与补发

默认每个世界保留最近 **50 条记录**，所有维度共享。记录公开玩家聊天，以及公开的进入、退出、死亡、进度公告。多行消息仍计为一条。每次成功入服后，在当前 tick 结束、原版完成连接初始化后，从旧到新发送已保留且启用的记录，包括本次进入公告（需启用且确实广播）。

初版不记录私聊、队伍聊天、限制接收范围的死亡消息、命令输出、`/say`、`/me`、`/tellraw` 和外部聊天桥接。采集依据通过 Fabric 拦截检查的全服广播及原版消息类型；替换这些路径或伪造原版事件组件的模组可能需要专门适配。

保留富文本、名称、颜色、翻译组件及悬浮信息；只添加整段开始、结束提示，不在每条消息前添加标记或时间。遵守过滤信息和接收者的聊天可见性设置。补发和模组提示不会再次写入历史。

初版对**所有入服玩家**发送最近记录，包括首次进入和快速重连的玩家，不追踪个人已读位置，也没有玩家查询或分页命令。

## 配置

配置属于游戏或服务端安装目录，同一安装中的单人存档共用配置，但历史互相隔离。

```json
{
  "historyLimit": 50,
  "events": {
    "join": true,
    "leave": true,
    "death": true,
    "advancement": true
  },
  "replayMode": "auto",
  "showEmptyHistory": true,
  "showConfigErrors": true
}
```

| 配置项 | 含义 |
| --- | --- |
| `historyLimit` | 正 64 位整数。不设额外固定上限，不预分配对应容量；仍受实际内存、磁盘和客户端限制。 |
| `events.join`、`events.leave`、`events.death`、`events.advancement` | 控制该类事件的采集和显示。关闭后旧记录仍占容量，在自然淘汰前重新开启可再次显示。 |
| `replayMode` | `auto` 在服务端有效安全策略允许时发送未签名玩家聊天，否则回退系统消息；`system` 始终使用系统消息。事件始终使用系统消息。 |
| `showEmptyHistory` | 没有可发送记录时显示提示。 |
| `showConfigErrors` | 配置出错时在入服补发结尾追加红色提示，与空历史提示开关独立。 |

缩小容量立即淘汰旧记录，扩大容量不能恢复已淘汰内容。缺少字段使用默认值，未知字段或无效值会被拒绝。启动时配置无效会保留文件并使用默认值；重载失败保留上一次有效配置。成功加载或命令保存有效配置后解除错误状态。

## 管理命令

控制台、OP2 及以上玩家、单人或局域网世界主人可管理。主人无需开启作弊，普通局域网访客无权操作。具备对应命令权限的命令方块也可以执行。

```text
/chathistory config
/chathistory config get historyLimit
/chathistory config set historyLimit 100
/chathistory config set events.death false
/chathistory config set replayMode system
/chathistory reload
/chathistory status
/chathistory clear
```

命令修改经过校验、保存后立即生效。`reload` 加载手动修改的文件；`status` 显示保留条数、可见条数、有效发送模式、配置和存储状态，以及待写任务数。发生过损坏恢复后，本次运行的状态会持续保留恢复警告，详情见日志。

`clear` 清空当前世界内存记录及恢复副本（包括隔离的损坏历史），取消尚未开始的旧快照写入，并等待正在进行的写入完成。仅在主文件及备份均重置后报告成功；失败会明确提示，并在下次保存或停服时重试。清空之后新到达的消息正常保留，不影响外部备份。

玩家语言为 `zh_cn` 时使用简体中文，其他语言使用英文。控制台和日志使用英文，不需要客户端语言资源包。

## 时间、安全聊天及窗口限制

存储及未签名玩家聊天数据包保留事件提供的时间。如果原版已将未签名输入重建为接收时间，就保存该时间。但 Minecraft 26.3 客户端会在当前回放路径的未签名验证阶段重建消息体，将时间改为当前接收时间；Chat Patches 8.0.0 随后读取的也是该时间，**目前不能通过其自带时间栏显示历史发送时间**。数据包保留时间不等于客户端显示原始时间。

初版不保存原签名或历史会话公钥。回放临时提供不列入在线名单的离线发送者身份，并在完成后恢复当前在线玩家的聊天会话状态。启用安全配置强制验证时，`auto` 回退系统消息；系统消息**没有原始聊天时间字段**。设置 `enforce-secure-profile=false` 仅允许 `auto` 使用未签名玩家聊天路径，**不能解决上述时间显示问题**；`online-mode` 可以保持开启。本模组不会修改这些设置。

未签名历史不是安全签名聊天。客户端的“**仅显示安全聊天**”选项可能隐藏它们，服务端无法检测这个开关。如需系统消息发送方式，可设为 `system`。客户端聊天可见性和其他模组也会影响最终显示。

原版最多保留 100 条聊天消息及 100 行渲染文本。长消息会换行，因此默认 50 条也可能超出可见行数。开始、结束及错误提示不计入 `historyLimit`，但仍占聊天窗口行数。

**兼容性状态：**构建和自动化检查不等同于实际游戏验收。原版联机、单人及局域网、Chat Patches 时间显示仍需执行 [验证清单](docs/TESTING.zh-CN.md)，不能仅凭协议测试认定客户端兼容性已通过。

## 存储

历史位于每个世界的 `data/server_chat_history/history.json`，另有一份 `.bak` 恢复快照。版本化 JSON 保存到达顺序、事件时间、富文本、发送者身份、原始内容及过滤信息，公开聊天以可读形式保存，请据此管理存档备份。

普通记录在有变更的服务器 tick 末尾合并为一次不可变持久化快照，未变化的快照会复用；单独的后台线程进一步合并尚未开始的普通保存任务。配置调整和清空保留显式持久化边界，正常停服等待最终快照完成，包括最后一个 tick 之后收到的记录。使用临时文件和文件系统支持的原子替换。崩溃或 I/O 故障可能丢失尚未落盘的记录，这不是事务式聊天归档系统。

回放按世界惰性缓存已解码文本组件，供不同接收者共享；历史淘汰、缩容、清空和关闭时释放失效缓存。可见性、文本过滤、消息序号及聊天会话仍按接收者处理。回放仍在入场 tick 内发送全部已保留且启用的记录，此优化不引入分页或分 tick 回放。

主文件无效时隔离为 `.corrupt-<uuid>` 并尝试恢复备份；两者均不可用时保留损坏文件、记录错误并从空历史开始。如果连隔离都失败，将拒绝覆盖原文件，需要修复权限后重启或明确执行清空。存储失败时继续内存记录，在后续变更和停服时重试。

## 构建

```sh
./gradlew clean build
```

需要 Java 25。Gradle 9.6.1 Wrapper 会校验分发包校验和。产物为 `build/libs/server-chat-history-0.1.0.jar`，`-sources.jar` 仅供开发。测试位于 `src/test`，HTML 报告位于 `build/reports/tests/test/`。GitHub Actions 构建并上传 JAR 和测试报告，不自动发布版本。

内部按采集、不可变记录、容量管理、补发策略、原版发送、配置及存储分层。验证范围见 [验证清单](docs/TESTING.zh-CN.md)。
